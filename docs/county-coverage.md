# Served County Coverage

The set of counties the company services changes over time, so HISS treats this list as user-editable configuration rather than baked-in data.

## Where it lives

- Configured at runtime via the **Served Counties** modal in `index.html`.
- Persisted to `localStorage` under the key `hiss.servedCounties` as an array of `"STATE:County Name"` entries (e.g. `"MD:Frederick County"`).
- No defaults are shipped. A fresh install starts with an empty list, and all events are flagged gray ("not configured") until the coordinator checks counties off.

## Changing the list

1. Open `index.html`.
2. Click **Served Counties** in the top-right settings area.
3. Tick or untick counties. Changes save immediately to localStorage.
4. Close the modal. Existing results re-evaluate their served/unserved badges on the fly.

## Exporting / sharing

The modal has **Export** and **Import** buttons that round-trip the served list as JSON, so the coordinator can back it up or share it across browsers/machines without a server.

## localStorage schema (for implementers)

- **Key:** `hiss.servedCounties`
- **Value:** JSON-stringified array of `"STATE:County Name"` strings. Example:
  ```json
  ["MD:Frederick County","MD:Carroll County","VA:Fairfax County","DC:District of Columbia"]
  ```
- **State codes:** `VA`, `MD`, `PA`, `DC`, `NJ`, `DE`, `MO`, `IL`, `OH`, `KS`, `WV` (matching the `state` field in `data/zip-county.json`).
- **County name format:** canonical name from `data/counties.json` (e.g. `"Frederick"`, not `"Frederick County"`; `"Fairfax City"` for Virginia independent cities; `"District of Columbia"` for DC).
- **Empty / missing key:** treat as an empty array. Never seed defaults.

## Import / Export JSON shape

The modal's Export button serializes to a small wrapper for forward compatibility:

```json
{
  "version": 1,
  "exportedAt": "2026-04-24T12:34:56Z",
  "servedCounties": [
    "MD:Frederick County",
    "VA:Fairfax County"
  ]
}
```

The Import button accepts either the wrapped shape above or a bare array.

## Event-to-county match algorithm

County resolution runs three tiers in the pipeline (`pipeline/enrich.py`), not the frontend:

1. **Tier 1 — ZIP lookup**: extract ZIP from address, look up in `data/zip-county.json`.
2. **Tier 2 — text scan**: regex scan of address/venue/title for known county names.
3. **Tier 3 — city lookup**: extract city from address, look up in `data/city-county.json`.

First successful tier wins. The frontend then compares `"<state>:<county>"` against `hiss.servedCounties`:
- **Green (✓)** — key is in the set.
- **Red (✗)** — county known but not in the served set.
- **Gray (?)** — county could not be resolved.

## Virginia independent cities

Virginia has 38 independent cities that are county-equivalents (e.g. Fairfax City,
Staunton City, Salem City). These are stored in `counties.json` as `"X City"` and
resolved correctly:

- **Tier 1**: ZCTAs that majority-overlap a city FIPS are assigned to the city.
  Small cities whose ZCTAs are dominated by the surrounding county are not covered
  here — resolved by Tier 3 instead.
- **Tier 3**: Census place names (`"Staunton city"`) are mapped directly to the
  canonical independent-city entity (`"Staunton City"`) when it exists in
  `counties.json`, bypassing the surrounding-county ZIP derivation.

## Behavior notes

- The full county master list for all 11 target states is loaded from `data/counties.json` in `index.html`. The coordinator chooses which to mark as served.
- Changes in the modal take effect immediately — existing result rows re-evaluate without a page reload.
- Lookup tables are regenerated by `scripts/build-zip-county.sh` (Census ZCTA relationship files). Re-run when adding new target states.
